# 업무 기록 · 보고

프로젝트별 규칙이 아니라 **저장소를 가로지르는 개인 업무 기록 규칙**이다.

## 기록 위치 — 단일 출처

`C:\Users\PC\Documents\MEGA\Obsidian\anysell\11-업무일지\`

| 파일 | 용도 |
|---|---|
| `업무일지.md` | **일자별.** 한 파일에 누적. 최신 날짜가 맨 위 |
| `업무보고-YYYY-MM-DD.html` | 일일 보고 **붙여넣기용 서식본** |
| `주간보고.md` | **주차별.** 한 파일에 누적. 최신 주가 맨 위 |
| `주간보고-YYYY-MM-DD.html` | 주간 보고 붙여넣기용 서식본 |

- **"업무일지 써줘"** = 위 `업무일지.md`에 **오늘 날짜로** 항목을 맨 위에 추가하는 것. 날짜별 파일을 새로 만들지 않는다.
- **"주간보고 써줘"** = `주간보고.md`에 그 주차 항목을 맨 위에 추가. **주 마지막 날(금요일)에 쓴다.** 지난주 항목을 그대로 가져와 상태만 바꾼다 — 문구를 새로 지어내지 않아야 진척이 보인다.

## 주간보고는 롤링이다 — (완료)는 한 주만 노출된다

| 지난주 상태 | 이번 주에 할 일 |
|---|---|
| (완료) | **뺀다.** 이미 지난주에 보고했다 |
| (진행 중) → 끝났으면 | **(완료)로 적고, 다음 주에 뺀다** |
| (진행 중) → 아직이면 | (진행 중) 유지 |
| (진행 전) → 손댔으면 | (진행 중) 또는 (완료) |
| (진행 전) → 그대로면 | (진행 전) 유지 |
| 이번 주 새로 끝낸 것 | (완료)로 추가. 다음 주에 뺀다 |

- 어느 단계(`■`)의 항목이 전부 빠지면 **그 단계도 통째로 뺀다.**
- **쓸 내용이 적으면 (진행 전) 항목을 더 적어 채운다.** 앞으로 할 일을 미리 올려 두면 다음 주에 상태만 바꾸면 된다.
- 일일 보고(`업무일지.md`)는 롤링이 아니다 — 그날 상태를 전부 적는다. 롤링은 주간보고에만 적용된다.
- 각 저장소의 `worklog.md`·`docs/업무일지.md` 규칙은 **그대로 유효하다.** 볼트 기록은 그것과 별개로 남긴다.

## 보고 양식 (사내 그룹웨어)

일일 보고는 4개 대분류 트리, 주간 보고는 과제명 제목 + `■` 단계.

```
1. 긴급 처리 업무 → 없음        │  서버 배포 및 이중화 구축
2. 기타 지원 사항 → 없음        │  ■ 1차 — ...
3. 연구소 내부과제              │    (완료) 항목
  1-1. (완료) 과제명            │  ■ 2차 — ...
   ■ 단계명                     │    (진행 중) 항목
     → (완료) 항목 — 결과       │
4. 국가과제 → 없음              │
```

- 상태는 **(완료) · (진행 중) · (진행 전)** 세 가지. 없어진 항목은 (해당 없음) + 사유.
- **★ · 색 · 굵은 글씨를 쓰지 않는다.** "AI로 쓴 게 티난다"고 지적받은 사항이다. 평문으로만.
- **앞으로의 날짜·기한을 적지 않는다.** 목표일을 넣으면 그 날짜를 두고 캐묻게 된다. 「일자 미정」도 쓰지 않는다 — 날짜 얘기를 꺼내는 것 자체를 피한다. 이미 끝난 실적(「목표 09/30 → 완료」)은 성과라 남겨도 된다.
- **수치도 필요 없으면 뺀다.** 「89% → 84%」·「30분」처럼 적으면 그 숫자를 두고 질문이 붙고 약속이 된다. 수치·날짜는 계획서와 「실무 상세」에만.
- **곧 완료될 항목만 적는다.** (진행 중)으로 적히면 다음 주에 완료돼야 하고, 아니면 지워야 한다. 며칠 뒤 단계까지 미리 나열하지 않는다.
- **내부 기술 용어를 쓰지 않는다.** Replica Set → 복제 구성 · VIP → 접속 주소 · iDRAC → 원격 전원 제어 · write concern → 쓰기 확정 정책 · Arbiter → 투표 전용 멤버 · fencing → 전원 차단.
- **단, 제품·시스템 이름은 그대로 쓴다.** Rocket.Chat · Jenkins · JFrog · PostgreSQL · Yona · Blue-Green 배포 — 사용자 본인 보고에 그대로 등장하는 이름들이다. 이걸 「사내 메신저」·「빌드 도구」처럼 풀면 오히려 뭘 말하는지 모호해진다. 풀어 쓸 대상은 **구성 방식·부품 이름**이지 제품명이 아니다.
- 사용자 표기 습관은 유지 — 구분자 `—`·`·`, 항목 머리 `→`, 단계 머리 `■`.

## 파일 구조 — 보고 구간과 실무 상세를 분리한다

`업무일지.md`·`주간보고.md`는 **위쪽이 보고 양식(평문·그대로 복사 가능)**, 그 아래 `실무 상세`에 기술 내용(서버에 가한 변경·실측값·경로·수치·강조 허용)을 붙인다.

- **서버에 가한 변경은 실무 상세에 반드시 적는다.** 되돌리는 법까지. **없으면 「없음」이라고 명시**한다 — 빈칸은 "안 했다"인지 "안 적었다"인지 구분이 안 된다.
- **변경한 것과 조회만 한 것을 구분한다.** 장애 시 원인 추적의 출발점이 된다.
- 비밀번호·토큰·개인키는 어느 쪽에도 적지 않는다(글로벌 CLAUDE.md 「보안」 적용).

## 붙여넣기용 HTML 서식

맑은 고딕 · 줄간격 1.4 · 기본 10pt · 큰제목 14pt · 소제목 12pt를 **모든 줄에 인라인 `style`로** 넣는다(그룹웨어 편집기가 `<style>` 블록을 떼어내도 살아남게). 들여쓰기는 `margin-left`. 사용법 안내 박스는 복사 영역(`#copybox`) **밖**에 둔다.
